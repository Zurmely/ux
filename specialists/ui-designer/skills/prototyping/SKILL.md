# Prototyping

## When to prototype

- Chief or Research requests testable flows
- Complex conditional navigation
- Motion-dependent UX (link to Motion spec when ready)

## Guidelines

1. Prototype **only scoped flows**—label “out of scope” screens.
2. Use realistic content from copy deck or sensible placeholders (label `[PLACEHOLDER]`).
3. Set starting frame and device preset; document in spec sheet.
4. For user tests: note where prototype **differs** from final build (fake data, missing validation).

## Outputs

- Prototype URL in UI spec sheet
- Optional clip or walkthrough notes in Drive for Chief

## Sub-skill boundary

**Motion Designer** owns duration/easing spec; UI wires prototype transitions as approximation.
